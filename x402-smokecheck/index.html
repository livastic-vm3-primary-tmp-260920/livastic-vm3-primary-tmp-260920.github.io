Does your x402 API actually work in a browser?

Your endpoint can return HTTP 402 correctly and still be unusable for browsers. The browser may be unable to read PAYMENT-REQUIRED, or its payment retry may fail an OPTIONS preflight.

Test that buyer path before you assume zero payments mean zero demand. This tool sends a CORS OPTIONS preflight and an unsigned GET. A synthetic JSON POST requires separate endpoint-owner authorization; it never signs, spends, logs in, or submits a transaction.

What the report actually checks

Preflight: allowed Origin, request method and PAYMENT-SIGNATURE. Challenge: HTTP 402, visible PAYMENT-REQUIRED, suitable CORS exposure, and cache safety. It labels blockers and warnings, but it cannot confirm signed retries, settlement or paid-resource delivery.

Privacy / money: No analytics or wallet connector on this page. CLI probes require your explicit endpoint-owner flag, discard response bodies and never send payment signatures. Do not include confidential URLs, API tokens or wallet recovery information.
