What this tool does and does not do

Only if your locally reviewed CSV already contains an explicit closing event UTC timestamp, signed realized PnL amount and actual settlement token, choose those exact fields below. This outputs a candidate Koinly Simple CSV with exact headers Koinly Date, Amount, Currency, Tag, Description; positive PnL is a deposit and negative PnL is a withdrawal, tagged realized gain as specified in Koinly's futures PnL documentation.

See the exact Koinly Simple CSV schema and tag rules before accepting any candidate import.

It does not infer Nado's raw field names, reconstruct realized PnL from fills, convert mark-to-market/open positions, compute exchange rates or tax, handle partial closes, funding charges, fees or transfers, reconcile duplicates across APIs or prove a report is accepted by Koinly. Each source row must already represent exactly one completed PnL event. Incorrect source columns will generate wrong results even if syntactically valid.
